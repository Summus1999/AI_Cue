# AI_Cue 商业化改进方案

## 目标

把 AI_Cue 从“功能型技术项目”推进到“可被普通求职者理解、上手、持续使用并愿意付费的面试训练产品”。

当前项目已经具备较强的技术底座：AI 聊天、语音输入、截图题解、透明窗口、RAG 知识库、会话持久化、复盘报告、多模型 Provider、导出能力、结构化日志和测试体系。商业化阶段不建议继续盲目堆功能，优先补齐以下能力：

- 新用户能在 3 分钟内完成第一次有效体验。
- 用户能围绕“岗位 JD + 简历 + 项目经历 + 技术资料”建立个人面试知识库。
- 产品能提供清晰的面试训练路径，而不是只提供一个通用聊天框。
- AI 输出结果能沉淀为复盘报告、知识盲点和后续训练计划。
- 错误、配置、模型失败、RAG 失败都能被用户理解和自助修复。
- 为未来收费、授权和版本区分预留最小可行能力。

## 商业化定位

### 当前定位问题

当前 README 里的产品能力比较多，容易让用户觉得这是一个“AI 工具箱”。它有面试助手、截图题解、知识库、复盘、导出、窗口透明等能力，但商业化表达不够聚焦。

另外，“不被会议软件捕捉”这类卖点存在合规风险。对外商业化时不建议把它作为主卖点。

### 推荐定位

推荐将对外定位调整为：

> AI_Cue 是面向求职者和技术候选人的 AI 面试训练与实时辅助工具。它可以根据用户的简历、岗位 JD、项目经历和技术资料建立个人知识库，提供模拟面试、实时问答、截图题解、知识盲点分析和面试复盘报告。

### 对外主卖点

- 个性化：基于简历、JD、项目经历和技术资料生成回答。
- 可追溯：RAG 回答带 citation，用户知道答案来自哪里。
- 可训练：支持模拟面试、复盘评分、知识盲点和改进建议。
- 低干扰：支持透明窗口、紧凑模式和快捷键，提高面试练习效率。
- 多模型：支持 Qwen、OpenAI Compatible、Claude 和私有化模型。

### 不建议作为主卖点的内容

- 不被会议软件捕捉。
- 面试作弊暗示。
- 绕过平台限制。
- 规避监控。

这些能力可以作为“窗口体验”“低干扰模式”“专注模式”描述，不要作为增长文案核心。

## 用户分层

### 目标用户一：技术求职者

典型场景：

- 准备字节、阿里、腾讯、美团、快手等技术岗面试。
- 需要围绕简历项目、岗位 JD、八股文、算法题做系统训练。
- 希望把过往项目经历包装成更清晰的面试表达。

核心价值：

- 快速生成项目讲述话术。
- 模拟面试官追问。
- 发现知识盲点。
- 输出复盘报告。

### 目标用户二：转岗或校招生

典型场景：

- 缺少面试经验。
- 不知道如何把项目和岗位 JD 对齐。
- 需要大量模板和练习路径。

核心价值：

- 提供面试模板。
- 提供结构化训练流程。
- 给出改进建议。

### 目标用户三：职业辅导者或培训机构

典型场景：

- 为学员批量做模拟面试。
- 需要导出报告。
- 需要追踪学员进步。

核心价值：

- 复盘报告。
- 历史记录。
- 趋势对比。
- 批量导出。

## 当前项目主要短板

## 1. 首次使用路径不完整

当前用户打开产品后，需要自己理解模型配置、知识库、RAG、面试模式、截图题解和复盘功能。对技术用户也许可以接受，但对商业化产品不够友好。

改进方向：

- 增加首次启动引导。
- 引导用户配置模型 API Key。
- 引导用户创建第一个知识库。
- 引导用户导入简历、岗位 JD 和项目资料。
- 引导用户选择训练目标。
- 最后进入一次示例模拟面试。

## 2. 知识库闭环缺少 UI 入口

README 已明确写到：`createKnowledgeBase` 后端和 store 已具备，但界面里没有单独的新建知识库按钮。

这是商业化前必须补齐的基础能力。否则普通用户无法完整使用 RAG。

改进方向：

- 在知识库页面增加“新建知识库”按钮。
- 支持知识库名称和描述。
- 创建后自动选中。
- 空知识库显示导入引导。
- 删除知识库时二次确认。

## 3. 面试场景还没有模板化

当前项目有助手模式和面试官模式，但还不够产品化。用户进入聊天框后仍然需要自己组织 Prompt。

改进方向：

- 新增面试模板系统。
- 支持简历深挖、JD 匹配、项目追问、八股文问答、算法题讲解、行为面试等模板。
- 模板可以自动拼接用户背景、当前知识库、面试模式和上下文策略。

## 4. 复盘报告需要更像交付物

复盘能力已经存在，但商业化产品需要让报告成为用户愿意付费的结果。

改进方向：

- 每次模拟面试结束后生成完整报告。
- 报告包含评分、问题列表、知识盲点、改进建议、推荐练习。
- 支持历史报告列表。
- 支持多次报告趋势对比。
- 支持 PDF / Markdown 导出。

## 5. 错误提示还不够商业化

AI 产品的失败场景很多：API Key 错误、余额不足、模型超时、RAG 无文档、Embedding 失败、OCR 不可用、网络中断。商业化产品必须把这些失败解释成人话。

改进方向：

- 统一错误模型。
- 每类错误给出明确原因和下一步操作。
- 在 UI 中提供“去设置”“重试”“查看日志”“导入文档”等快捷操作。

## 6. 功能开关缺失

当前项目所有功能都是全开全关，缺少细粒度的功能开关控制。

改进方向：

- 建立统一的功能开关（Feature Gate）系统。
- 设置页中可独立控制各功能模块的启用/禁用。
- 功能开关状态持久化到配置文件。
- 关闭非核心功能时对应的 UI 入口自动隐藏。

## 改进优先级

## P0：必须先做

### P0.1 知识库新建入口

原因：

这是当前 RAG 商业闭环里最明显的产品缺口。底层能力已有，只缺 UI 接入，收益高，风险低。

用户价值：

- 用户可以自己创建知识库。
- 用户可以导入简历、JD 和技术资料。
- 用户可以体验“基于个人资料回答”的核心卖点。

技术范围：

- `src/components/KnowledgeBasePanel.tsx`
- `src/store/rag.ts`
- `src/services/ragService.ts`
- `src/components/KnowledgeBasePanel.test.tsx`

验收标准：

- 知识库页面有“新建知识库”入口。
- 用户可以输入名称和描述。
- 创建成功后自动选中新知识库。
- 新知识库为空时展示导入引导。
- 创建失败时展示可理解错误。
- 原有删除、切换、统计、导入功能不受影响。

### P0.2 首次启动引导

原因：

商业化产品必须让用户知道第一步做什么。没有 onboarding，复杂 AI 工具很容易流失。

用户价值：

- 用户第一次打开就知道如何配置模型。
- 用户知道为什么要导入简历和 JD。
- 用户能快速进入一次模拟面试。

技术范围：

- 新增 `src/components/OnboardingDialog.tsx`
- 修改 `src/store/config.ts`
- 修改 `src/App.tsx`
- 可能新增 `src/components/OnboardingDialog.test.tsx`

引导流程：

1. 欢迎页：说明 AI_Cue 能做什么。
2. 模型配置页：选择 Provider，填写 API Key 或跳过。
3. 知识库页：创建第一个知识库。
4. 资料导入页：引导导入简历、JD、项目文档。
5. 模式选择页：选择模拟面试或实时辅助。
6. 完成页：进入聊天或知识库页面。

验收标准：

- 首次启动显示引导。
- 完成后不再重复弹出。
- 设置页可重新打开引导。
- 跳过引导不会影响原有功能。
- 引导状态持久化。

### P0.3 面试模板系统

原因：

用户不应该自己写复杂 Prompt。模板能把产品从“聊天工具”变成“面试训练工具”。

用户价值：

- 一键选择训练目标。
- 回答更贴合真实面试。
- 降低 Prompt 编写门槛。

技术范围：

- 新增 `src/services/interviewTemplates.ts`
- 修改 `src/store/config.ts` 或新增模板 store
- 修改 `src/App.tsx`
- 修改聊天请求构建逻辑，接入模板 Prompt
- 新增模板测试

首批模板：

- 简历深挖：围绕简历项目追问技术细节、难点、指标和取舍。
- JD 匹配：根据岗位 JD 分析候选人经历如何匹配。
- 项目经历包装：把项目讲成 STAR 或“背景、目标、方案、难点、结果”结构。
- 八股文问答：围绕技术知识点追问原理、场景和边界。
- 算法题讲解：先澄清题意，再给思路、复杂度和代码。
- 行为面试：围绕冲突、协作、压力、失败经历提问。

验收标准：

- 聊天页面能选择模板。
- 模板选择会影响后续请求 Prompt。
- 切换模板不破坏会话历史。
- 模板可以和 RAG context 同时工作。
- 模板关闭后恢复普通聊天。

## P1：提升付费感

### P1.1 复盘报告增强

原因：

报告是最容易形成付费感的产物。用户愿意为“明确知道自己哪里弱、下一步怎么练”付费。

建议能力：

- 面试结束后生成复盘报告。
- 报告结构化展示评分、亮点、问题、知识盲点和行动建议。
- 支持历史报告列表。
- 支持同一岗位多次面试趋势对比。
- 支持导出 PDF / Markdown。

报告结构建议：

```text
总体评分
表达清晰度
技术深度
项目可信度
岗位匹配度
知识盲点
高频追问
建议复习资料
下一次训练计划
```

验收标准：

- 用户能从会话生成报告。
- 报告可持久化。
- 报告可再次打开。
- 报告可导出。
- 报告能引用原始问答证据。

### P1.2 统一错误体验

原因：

商业化 AI 产品的核心体验不是永不失败，而是失败后用户知道怎么办。

建议错误分类：

- 配置错误：缺少 API Key、Base URL 错误、模型名错误。
- 账户错误：余额不足、鉴权失败、限流。
- 网络错误：超时、断网、服务不可达。
- RAG 错误：无 ready 文档、embedding 失败、索引未完成。
- OCR 错误：系统能力不可用、文件无法解析。
- 导出错误：PDF 生成失败、文件权限不足。

UI 建议：

- 错误标题使用用户语言。
- 错误详情保留技术信息。
- 提供下一步按钮。
- 允许复制诊断信息。

验收标准：

- 常见错误不再只显示原始异常。
- 用户能从错误卡片进入设置或重试。
- 开发者仍能看到详细日志。

### P1.3 训练路径和任务清单

原因：

商业产品需要让用户持续回来，而不是一次性使用。

建议能力：

- 用户选择目标岗位。
- 系统生成 7 天或 14 天训练计划。
- 每天包含模拟面试、知识点复习、项目追问、算法练习。
- 完成后更新进度。

验收标准：

- 用户能创建训练计划。
- 训练计划能持久化。
- 任务完成状态可记录。
- 复盘报告能影响下一次训练建议。

## P2：功能开关与反馈闭环

### P2.1 统一功能开关

原因：

需要细粒度的功能开关控制，让用户可以按需启用或禁用各模块。

建议能力：

- 统一的功能开关（Feature Gate）系统。
- 设置页中可独立控制：RAG 增强检索、复盘报告、面试模板、训练计划等。
- 功能开关状态持久化。
- 关闭功能时对应的 UI 入口自动隐藏。

验收标准：

- 设置页有"功能开关"区域。
- 每个功能可独立开关。
- 关闭后 UI 入口隐藏。
- 开关状态持久化。

### P2.2 数据与反馈闭环

原因：

商业化需要知道用户在哪里流失、哪些功能被使用、错误在哪里发生。

建议能力：

- 本地匿名使用统计开关。
- 关键路径埋点：启动、配置模型、创建知识库、导入文档、发送消息、生成报告、导出报告。
- 错误日志导出。
- 用户反馈入口。

注意：

由于项目涉及面试和个人资料，默认不要上传用户内容。商业化早期建议只做本地日志导出和用户主动反馈。

验收标准：

- 设置页有隐私说明。
- 用户可关闭统计。
- 日志导出不包含 API Key。
- 用户能复制诊断信息。

## 推荐实施路线

## 第一阶段：补齐核心闭环

目标：

让一个新用户可以完成“创建知识库 → 导入资料 → 选择模板 → 开始模拟面试”的完整路径。

任务：

1. 新增知识库创建入口。
2. 新增首次启动引导。
3. 新增面试模板系统。
4. 补齐相关测试。

建议交给 DeepSeek 的第一条任务：

> 只实现知识库创建入口和空状态引导。不要重构 RAG 后端，不要新增无关抽象。沿用现有 Zustand store、ragService 和 KnowledgeBasePanel 的风格。修改后补齐组件测试，并确保 `npm run build` 通过。

## 第二阶段：强化面试产品感

目标：

让用户感觉 AI_Cue 是面试训练产品，而不是通用 AI Chat。

任务：

1. 面试模板系统接入聊天请求。
2. 新增岗位目标配置。
3. 新增 JD / 简历导入引导。
4. 新增项目经历包装模板。

建议交给 DeepSeek 的任务：

> 实现面试模板系统。模板先用前端静态配置，不接后端。支持模板选择、持久化和请求 Prompt 注入。保留普通聊天模式。补齐模板选择和 Prompt 拼接测试。

## 第三阶段：复盘报告产品化

目标：

让每次模拟面试都能产出用户愿意保存和导出的报告。

任务：

1. 优化报告结构。
2. 新增历史报告列表。
3. 报告引用原始问答证据。
4. 强化 PDF / Markdown 导出。

建议交给 DeepSeek 的任务：

> 增强面试复盘报告。新增报告列表和报告详情入口。报告必须持久化，并能从历史会话再次打开。不要改动现有聊天主流程，只在复盘模块内扩展。

## 第四阶段：稳定性和错误体验

目标：

降低用户遇到配置和模型问题时的挫败感。

任务：

1. 梳理错误类型。
2. 新增统一错误卡片。
3. 为 Provider、RAG、OCR、导出错误提供用户友好提示。
4. 增加复制诊断信息能力。

建议交给 DeepSeek 的任务：

> 设计并接入统一错误展示组件。先覆盖模型配置错误、RAG 无 ready 文档、Embedding 失败和网络失败四类场景。不要改变底层错误类型太多，优先在服务层做映射。

## 第五阶段：功能开关与反馈

目标：

建立统一的功能开关系统和本地反馈机制。

任务：

1. 新增功能开关（Feature Gate）系统，统一管理各模块的启用/禁用。
2. 设置页集成功能开关区域。
3. 关闭功能时对应 UI 入口自动隐藏。
4. 新增本地使用统计开关和日志导出能力。

建议交给 DeepSeek 的任务：

> 新增统一功能开关系统。用 AppConfig 中的 featureGates 字段管理开关状态，创建 FeatureGate 组件包装需要受控的 UI 入口。设置页中提供各功能的独立开关。不要引入 license、版本区分或支付相关代码。

## 详细任务拆分

## 任务 1：知识库创建入口

### 任务 1 目标

用户能在知识库页面自行创建知识库。

### 任务 1 可能涉及文件

- `src/components/KnowledgeBasePanel.tsx`
- `src/components/KnowledgeBasePanel.test.tsx`
- `src/store/rag.ts`
- `src/store/__tests__/rag.test.ts`
- `src/services/ragService.ts`

### 任务 1 功能要求

- 页面顶部增加“新建知识库”按钮。
- 点击后出现弹窗或内联表单。
- 表单字段包括名称和描述。
- 名称必填，描述可选。
- 提交时调用现有 create knowledge base 能力。
- 创建成功后自动刷新列表并选中新知识库。
- 创建失败时显示错误。
- 当前没有知识库时展示空状态说明和创建按钮。

### 任务 1 非目标

- 不做云同步。
- 不做知识库分享。
- 不做多用户协作。
- 不修改后端 Schema，除非现有接口确实无法支持。

### 任务 1 验收标准

- 新建成功。
- 新建后自动选中。
- 空状态可引导用户创建。
- 删除后列表状态正确。
- 原有导入、重建、异常重试不回归。

## 任务 2：首次启动引导

### 任务 2 目标

让新用户知道如何完成第一次有效体验。

### 任务 2 可能涉及文件

## 技术原则

## 1. 不重构已有 RAG 后端

RAG 主线已经完成度较高。商业化第一阶段不应该重写检索、embedding、OCR 或数据库 Schema。优先补 UI、流程和错误体验。

## 2. 先做静态模板，不做复杂模板编辑器

面试模板先用前端静态配置。不要一开始就做模板市场、模板编辑器、模板分享。

## 3. 功能开关做轻量级，不引入授权体系

不做 license、账号、支付和云同步。功能开关仅用于用户自主控制各功能模块的启用/禁用，不涉及版本区分或功能锁定。

## 4. 保持隐私优先

简历、JD、面试记录和知识库都属于敏感信息。默认不上传用户内容。日志导出时不能包含 API Key。

## 5. 每个阶段都要有可验收结果

不要让模型一次性改多个模块。每次只推进一个明确子任务，并跑对应测试和构建。
