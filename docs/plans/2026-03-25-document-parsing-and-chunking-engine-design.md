# 文档解析与智能分块引擎设计文档

日期：2026-03-25

## 1. 目标

为 AI_Cue 的 RAG 基础设施补齐“文件级内容输入”能力，支持以下输入类型：

- Markdown
- PDF（仅文本型 PDF，不做 OCR）
- 纯文本
- 常见代码文件

本阶段只实现“解析 + 结构化分块 + 命令接口”，不实现知识库管理 UI，不实现批量导入界面，不实现 Embedding 入库持久化。

## 2. 设计边界

### 2.1 本阶段包含

- 文件类型识别与基础校验
- Markdown 结构解析
- PDF 页级文本提取
- 纯文本段落解析
- 代码文件结构化切块
- 基于结构边界的智能分块
- Tauri 命令：解析文档、分块文档

### 2.2 本阶段不包含

- OCR
- 扫描版 PDF
- 知识库导入 UI
- 文档持久化表
- 文档向量化与检索链路打通

## 3. 核心原则

### 3.1 文件是主对象

虽然本阶段不落库，但解析结果必须保留文件级元数据，确保后续接入知识库时不需要推倒重来。

### 3.2 结构优先

分块时优先保留文档天然结构：

- Markdown 标题层级
- PDF 页边界
- 纯文本段落边界
- 代码文件的符号边界

只有块过大时，才退化为窗口切分。

### 3.3 对后续 RAG 友好

所有块都要保留来源元数据，至少包括：

- 源文件路径
- 文件类型
- 标题路径
- 页码
- 语言
- 原始起止偏移

## 4. 数据模型

### 4.1 ParsedDocument

表示一个已解析的文件：

- metadata：文件级元数据
- blocks：结构块列表
- total_pages：PDF 页数
- total_chars：总字符数

### 4.2 ParsedBlock

表示一个结构块：

- block_kind：标题、段落、列表、引用、代码、代码符号等
- text：结构块文本
- heading_path：所属标题路径
- page_number：PDF 页码
- language：代码语言
- symbol：代码符号名
- start_offset / end_offset：原文偏移

### 4.3 DocumentChunk

表示最终用于后续向量化的块：

- chunk_index：块序号
- text：块文本
- chunk_type：文本或代码
- source_path：来源文件
- document_type：来源类型
- title：文档标题
- heading_path：标题路径
- page_number：页码
- language：语言
- start_offset / end_offset：覆盖范围
- block_count：包含的结构块数量

## 5. 解析策略

### 5.1 Markdown

识别：

- `#` 到 `######` 标题
- fenced code block
- 列表项
- 引用块
- 段落

标题路径采用栈维护，后续块继承最近标题上下文。

### 5.2 PDF

使用文本型 PDF 提取库逐页抽取文本。

每页文本按空行切为多个段落块，并保留页码。若页内无法识别有效段落，则整页回退为单块。

### 5.3 纯文本

按空行切段。长段落在分块阶段再按句子边界和窗口切分。

### 5.4 代码文件

先识别语言，再做轻量结构切分：

- import / use / package / include 区
- 连续注释区
- 函数 / 类 / 结构体 / 接口 / 模块等符号起始
- 普通代码区

不做 AST 级精确切分，但要尽量避免把相邻函数混成一个块。

## 6. 智能分块策略

### 6.1 分块优先级

1. 先按结构块切
2. 结构块可合并时再合并
3. 超过上限时按语义或行窗口二次切分

### 6.2 合并规则

优先合并满足以下条件的相邻结构块：

- 同一标题路径
- 同一 PDF 页
- 都是文本型块
- 合并后长度未超过 `max_chunk_size`

### 6.3 二次切分

- 文本块：按句子边界切分，保留 overlap
- 代码块：按行窗口切分，保留 overlap

## 7. 接口设计

### 7.1 后端命令

- `rag_parse_document(path)`
  返回结构化解析结果

- `rag_chunk_document(path, config?)`
  返回最终可用于后续向量化的分块结果

### 7.2 前端服务层

先只补服务接口和类型定义，不接入 UI。

## 8. 实施分阶段

### 阶段一

### 阶段三

## 9. 风险与约束

- PDF 文本提取质量高度依赖源 PDF，本阶段不解决扫描件问题
- 代码结构切分采用启发式规则，复杂语法场景可能不如 AST 精确
- 文本块的“语义边界”仍是轻量实现，不引入重量级 NLP 依赖

## 10. 验收标准

- Markdown 能正确识别标题与代码块
- PDF 能逐页输出文本块并保留页码
- 纯文本能按段落切块
- 常见代码文件能在函数/类附近形成较稳定的结构块
- `rag_parse_document` 和 `rag_chunk_document` 可直接调用
- `cargo check` 与 `npm run tauri dev` 通过
