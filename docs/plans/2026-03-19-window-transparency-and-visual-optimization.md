# P0 - 窗口透明度与视觉优化 需求规格说明

## 1. 概述

### 1.1 模块定位

本模块为 **P0 优先级**，原因如下：

- **核心场景强依赖**：AI_Cue 的主要使用场景是作为悬浮窗叠加在视频面试画面（如腾讯会议）之上。窗口的透明度、交互穿透能力直接决定用户能否正常进行面试——若窗口完全遮挡面试画面或干扰鼠标操作，产品将无法使用。
- **用户体验基础设施**：窗口位置记忆、紧凑模式等功能减少用户每次启动时的重复配置成本，是提升日常使用效率的基础能力。

### 1.2 核心用户场景

用户正在进行视频面试，将 AI_Cue 窗口置于屏幕右侧或角落，需要：

1. 透过半透明的 AI_Cue 窗口看到面试官画面和共享屏幕内容
2. 在需要操作面试软件时，鼠标点击能穿透 AI_Cue 窗口到达下层应用
3. 在需要查看 AI 回答时，快速让窗口变得清晰可读
4. 每次启动应用时，窗口自动出现在上次使用的位置和大小
5. 在屏幕空间紧张时，将窗口切换为仅显示最新回答的紧凑形态

### 1.3 设计目标

**让 AI_Cue 在视频面试场景中"存在但不打扰"——用户需要时清晰可见，不需要时隐于背景。**

---

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| **窗口透明度** | 窗口整体的不透明程度，100% 表示完全不透明，20% 表示高度透明（仅保留 20% 不透明度） |
| **穿透模式** | 一种窗口状态，在该状态下，鼠标点击事件不会被窗口拦截，而是传递至窗口下方的其他应用程序 |
| **交互区域** | 窗口内需要响应用户操作的 UI 元素区域，包括：输入框、按钮、滑块、可滚动内容区、可拖拽的标题栏 |
| **非交互区域** | 窗口内除交互区域外的背景区域，包括：空白边距、纯展示性背景、元素之间的间隙 |
| **紧凑模式** | 一种窗口显示模式，将完整界面收缩为仅显示最新一条 AI 回答的小型悬浮窗 |
| **完整模式** | 与紧凑模式相对，指显示完整对话界面的默认窗口模式 |
| **悬停恢复** | 鼠标进入窗口区域时，自动将透明度临时恢复为 100% 的行为 |

## 3. 功能需求详述

### 3.1 窗口透明度滑块调节

#### 功能描述

用户可通过滑块控件调节 AI_Cue 主窗口的整体透明度，调节过程中实时预览效果，调节完成后自动保存设置。

#### 交互细节

| 属性 | 规格 |
|------|------|
| 控件位置 | 设置面板（SettingsPanel）内，作为独立配置项 |
| 控件类型 | 水平滑块（Slider） |
| 取值范围 | 20% ~ 100% |
| 步长 | 5%（滑块拖动时吸附到 5% 的整数倍） |
| 默认值 | 80%（首次安装时） |
| 数值显示 | 滑块右侧显示当前百分比数值，格式为"XX%"  |

#### 实时预览行为

- 用户拖动滑块过程中，主窗口透明度**同步实时变化**，无需松开鼠标或点击确认
- 预览延迟要求：滑块位置变化到窗口透明度变化的延迟 ≤ 50ms

#### 持久化

- 用户调节透明度后，新值**立即自动保存**至本地配置存储
- 下次启动应用时，自动应用上次保存的透明度值
- 存储键名建议：`window.opacity`

#### 边界条件

| 场景 | 预期行为 |
|------|----------|
| 滑块拖动到最小值 20% | 窗口保持 20% 不透明度，不可低于此值 |
| 滑块拖动到最大值 100% | 窗口完全不透明 |
| 存储值被外部损坏或丢失 | 使用默认值 80% |
| 悬停恢复功能开启时 | 滑块调节的是"鼠标离开后"的目标透明度，悬停时始终为 100% |

### 3.2 鼠标悬停自动恢复不透明

#### 功能描述

当鼠标指针进入 AI_Cue 窗口区域时，窗口透明度自动临时恢复为 100%（完全不透明），便于用户阅读内容；当鼠标移出窗口区域后，透明度自动恢复为用户设定的值。

#### 触发与恢复的详细行为

**进入窗口（触发恢复不透明）：**

- 触发条件：鼠标指针从窗口外部移入窗口边界内
- 响应时机：**立即**（无延迟）
- 动画效果：透明度从当前设定值渐变至 100%，动画时长 150ms，使用 ease-out 缓动

**离开窗口（恢复设定透明度）：**

- 触发条件：鼠标指针从窗口内部移出窗口边界外
- 延迟策略：鼠标移出后**等待 300ms**，若期间鼠标未重新进入，则开始恢复透明度
- 延迟目的：避免鼠标在窗口边缘短暂划过时造成透明度闪烁
- 动画效果：透明度从 100% 渐变至用户设定值，动画时长 200ms，使用 ease-in 缓动

#### 与透明度滑块的联动关系

- 滑块设定的透明度值为"基准透明度"，即鼠标不在窗口内时的目标透明度
- 悬停恢复时的目标透明度固定为 100%，不受滑块影响
- 若用户将滑块设为 100%，则悬停恢复行为无可见效果（因基准已是 100%）

#### 可配置项

| 配置项 | 说明 |
|--------|------|
| 功能开关 | 用户可在设置面板中关闭此行为，关闭后鼠标悬停不会改变透明度 |
| 存储键名建议 | `window.hoverRestore.enabled`（布尔值） |
| 默认状态 | 开启（true） |

#### 边界条件

| 场景 | 预期行为 |
|------|----------|
| 功能关闭时 | 鼠标进入/离开窗口不触发任何透明度变化 |
| 穿透模式开启时 | 见 3.3 节协同逻辑说明 |
| 鼠标在 300ms 延迟期内重新进入 | 取消恢复透明度的计时，窗口保持 100% 不透明 |
| 窗口正在执行进入动画时鼠标移出 | 立即中断进入动画，开始 300ms 延迟计时 |
| 窗口失去焦点但鼠标仍在窗口内 | 保持 100% 不透明（以鼠标位置为准，非焦点状态） |

### 3.3 穿透模式

#### 功能描述

穿透模式是一种特殊的窗口交互状态。开启后，窗口的**非交互区域**对鼠标点击事件透明，点击会穿透至下层应用（如腾讯会议）；**交互区域**仍可正常响应点击。

#### 开关位置与状态展示

| 属性 | 规格 |
|------|------|
| 开关位置 | 主窗口标题栏右侧，紧邻最小化按钮左侧，使用图标按钮 |
| 图标设计 | 关闭状态：实心鼠标指针图标；开启状态：虚线/半透明鼠标指针图标 |
| 状态提示 | 鼠标悬停显示 tooltip："点击穿透：关闭"或"点击穿透：开启" |
| 视觉反馈 | 开启时图标高亮或添加激活态指示（如底色变化） |

#### 交互区域与非交互区域的精确定义

**交互区域（不可穿透，始终响应本应用点击）：**
- 标题栏（包含窗口拖拽区域、关闭/最小化按钮、穿透模式开关）
- 消息输入框及发送按钮
- 设置面板内的所有控件
- 会话列表区域（可滚动、可点击选择）
- 消息内容区域（可滚动、可选择文本）
- 所有可见的按钮、滑块、开关、下拉框等交互控件
- 紧凑模式下的展开按钮

**非交互区域（穿透模式下可穿透）：**
- 窗口背景色区域
- 元素之间的空白间隙（padding/margin 区域）
- 无交互功能的装饰性边框

#### 穿透行为的技术约束说明

- 穿透实现依赖 Windows 系统的 `WS_EX_TRANSPARENT` 或等效机制，需在 Tauri 窗口配置层面实现
- 穿透仅影响鼠标点击（mouse down/up/click），不影响鼠标移动（mouse move）事件——鼠标移动仍可被检测用于悬停恢复功能
- 穿透行为与窗口是否置顶无关，置顶窗口同样可以启用穿透

#### 与悬停恢复不透明的协同逻辑

| 穿透模式 | 悬停恢复 | 行为 |
|----------|----------|------|
| 关闭 | 开启 | 鼠标进入窗口任意区域即触发恢复不透明 |
| 开启 | 开启 | 鼠标进入**交互区域**时触发恢复不透明；鼠标在非交互区域移动不触发（因点击会穿透，用户意图是操作下层应用） |
| 关闭 | 关闭 | 透明度保持用户设定值不变 |
| 开启 | 关闭 | 透明度保持用户设定值不变 |

#### 安全退出机制

为确保用户在穿透模式下仍能操作本应用，提供以下机制：

1. **标题栏始终可交互**：标题栏区域在任何模式下都不穿透，用户可点击穿透开关关闭穿透模式
2. **全局快捷键**：提供快捷键（建议 `Ctrl+Shift+T`）切换穿透模式，即使鼠标无法点击到开关也可操作
3. **系统托盘菜单**：托盘图标右键菜单提供"关闭穿透模式"选项

#### 持久化

- 穿透模式状态**不持久化**，每次启动应用默认为关闭状态
- 理由：穿透模式是高度场景化的临时状态，误开启可能导致用户困惑

#### 边界条件

| 场景 | 预期行为 |
|------|----------|
| 穿透模式下尝试拖拽窗口 | 标题栏可正常拖拽（标题栏属于交互区域） |
| 穿透模式下窗口下方无其他应用 | 点击穿透至桌面 |
| 穿透模式下打开设置面板 | 设置面板内容属于交互区域，可正常操作 |
| 快速连续点击穿透开关 | 防抖处理，300ms 内多次点击仅响应最后一次 |

### 3.4 窗口位置和大小记忆

#### 功能描述

应用记住用户调整后的窗口位置和尺寸，下次启动时自动恢复，免去重复调整窗口的操作。

#### 保存时机

采用**多重保存策略**，确保数据不丢失：

| 触发事件 | 保存行为 |
|----------|----------|
| 窗口拖拽结束 | 立即保存新位置 |
| 窗口缩放结束 | 立即保存新尺寸 |
| 应用正常关闭 | 保存当前位置和尺寸 |
| 防抖定时保存 | 位置/尺寸变化后 500ms 内无新变化，则触发保存（覆盖上述立即保存，避免拖拽过程中频繁写入） |

**保存内容：**
- 窗口左上角坐标（x, y）
- 窗口尺寸（width, height）
- 当前是否为最大化状态（isMaximized）
- 当前是否为紧凑模式（isCompact）

#### 恢复逻辑

**启动时恢复流程：**

1. 读取存储的位置和尺寸数据
2. 检测当前连接的显示器配置
3. 验证存储位置是否在当前可用屏幕区域内
4. 若有效，恢复到存储位置和尺寸
5. 若无效，执行降级策略

**多显示器场景处理：**

| 场景 | 处理策略 |
|------|----------|
| 存储位置在主显示器 | 直接恢复 |
| 存储位置在副显示器，副显示器仍连接 | 直接恢复 |
| 存储位置在副显示器，副显示器已断开 | 执行降级策略 |
| 显示器分辨率变化导致位置超出 | 执行降级策略 |

**降级策略：**
- 将窗口移动到**主显示器的中央位置**
- 保持存储的尺寸（若尺寸超出屏幕则同时调整为屏幕的 80%）
- 在窗口标题栏显示一次性提示："窗口位置已自动调整"

#### 持久化方案

| 属性 | 建议 |
|------|------|
| 存储位置 | 与其他应用配置统一存储（现有配置存储机制） |
| 存储格式 | JSON |
| 存储键名 | `window.bounds`（包含 x, y, width, height, isMaximized, isCompact） |

#### 边界条件

| 场景 | 预期行为 |
|------|----------|
| 首次安装，无存储数据 | 使用默认位置（主显示器右下角）和默认尺寸（400×600） |
| 存储数据格式损坏 | 使用默认值，不报错 |
| 窗口被拖拽到屏幕边缘仅露出标题栏 | 允许保存此位置（用户可能有意为之） |
| 恢复时窗口完全超出所有屏幕 | 执行降级策略 |
| 紧凑模式下的位置 | 紧凑模式和完整模式各自独立记忆位置 |

### 3.5 紧凑模式

#### 功能描述

紧凑模式将完整的对话界面收缩为一个小型悬浮窗，仅显示最新一条 AI 回答，最大限度减少屏幕占用，同时保持关键信息可见。

#### 切换入口

| 入口 | 规格 |
|------|------|
| 标题栏按钮 | 位于最小化按钮左侧，使用折叠/收缩图标 |
| 全局快捷键 | `Ctrl+Shift+M`（M = Mini），可在快捷键设置中自定义 |
| 托盘菜单 | 右键菜单提供"切换紧凑模式"选项 |

**切换动画：**
- 完整模式 → 紧凑模式：窗口从当前尺寸渐变收缩至紧凑尺寸，动画时长 200ms
- 紧凑模式 → 完整模式：窗口从紧凑尺寸渐变扩展至完整尺寸，动画时长 200ms

#### 紧凑模式下的界面布局

**显示元素：**
- 精简标题栏（仅包含：拖拽区域、展开按钮、穿透模式开关、关闭按钮）
- 最新一条 AI 回答内容区域
- 若当前有语音识别进行中，显示识别状态指示器

**隐藏元素：**
- 会话列表侧边栏
- 历史消息记录
- 消息输入框
- 设置入口
- 用户消息

**窗口尺寸：**
- 默认紧凑尺寸：宽 320px，高自适应内容（最小 80px，最大 200px）
- 用户可拖拽调整紧凑模式下的尺寸，调整后的尺寸独立记忆

#### 显示内容规则

**最新一条 AI 回答的定义：**
- 当前活跃会话中，最近一条角色为 AI/Assistant 的消息

**内容截断策略：**

| 内容类型 | 处理方式 |
|----------|----------|
| 纯文本回答 | 显示前 200 字符，超出部分截断并显示"..."，文末显示"展开查看完整回答"可点击链接 |
| 包含代码块 | 代码块折叠为"[代码块]"占位符，点击展开完整模式 |
| 包含图片 | 显示缩略图（最大高度 60px），点击展开完整模式 |
| 内容为空/无 AI 回答 | 显示占位文案："等待 AI 回答..." |

**内容更新：**
- 当新的 AI 回答产生时（流式输出过程中），紧凑窗口内容实时更新
- 流式输出时显示动态光标指示正在生成

#### 恢复到完整模式的交互

| 交互方式 | 行为 |
|----------|------|
| 点击展开按钮 | 切换回完整模式 |
| 使用快捷键 `Ctrl+Shift+M` | 切换回完整模式 |
| 点击"展开查看完整回答"链接 | 切换回完整模式 |
| 双击紧凑窗口内容区域 | 切换回完整模式 |

#### 与透明度/穿透模式的联动

- 紧凑模式继承当前的透明度设置和穿透模式状态
- 紧凑模式下的交互区域重新定义为：标题栏、内容区域（可滚动查看截断内容）、展开按钮
- 紧凑模式下的非交互区域：仅窗口边框和微小边距

#### 持久化

- 紧凑模式状态持久化：若关闭应用时处于紧凑模式，下次启动恢复为紧凑模式
- 紧凑模式的窗口位置独立于完整模式记忆

#### 边界条件

| 场景 | 预期行为 |
|------|----------|
| 紧凑模式下切换会话 | 更新显示为新会话的最新 AI 回答 |
| 紧凑模式下新建会话 | 显示"等待 AI 回答..."占位文案 |
| 紧凑模式下收到新用户消息（通过其他方式如 API） | 不显示用户消息，等待 AI 回答后更新 |
| 展开按钮处于禁用状态（无） | 展开按钮始终可用 |
| 紧凑模式下打开设置 | 自动切换回完整模式后打开设置面板 |

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 透明度滑块响应 | 滑块位置变化到窗口透明度变化 ≤ 50ms |
| 悬停恢复动画帧率 | ≥ 30fps，确保渐变平滑无卡顿 |
| 模式切换响应 | 紧凑/完整模式切换动画启动 ≤ 100ms |
| 配置读写 | 配置保存/读取操作 ≤ 50ms |
| 窗口拖拽/缩放 | 无明显延迟，帧率 ≥ 60fps |

### 4.2 兼容性

| 维度 | 要求 |
|------|------|
| Windows 版本 | Windows 10 1903+ 及 Windows 11 全版本 |
| 多显示器 | 支持最多 4 台显示器，支持不同 DPI 混合配置 |
| 高 DPI | 支持 100%/125%/150%/175%/200% 缩放，UI 元素不模糊、不错位 |
| 显示器热插拔 | 断开/连接显示器后，窗口位置自动调整到可见区域 |

### 4.3 无障碍

| 要求 | 说明 |
|------|------|
| 键盘可操作性 | 透明度滑块可通过 Tab 聚焦，方向键调节 |
| 快捷键 | 所有模式切换均有对应快捷键，不依赖鼠标 |
| 屏幕阅读器 | 穿透模式、紧凑模式状态变化时发出 ARIA 通知 |

## 6. 验收标准

### 6.1 窗口透明度滑块调节

```gherkin
Scenario: 调节透明度滑块实时生效
  Given 用户打开设置面板
  When 用户将透明度滑块从 80% 拖动至 50%
  Then 主窗口透明度在拖动过程中实时变化
  And 松开鼠标后透明度稳定在 50%

Scenario: 透明度设置持久化
  Given 用户将透明度设置为 60%
  When 用户关闭并重新启动应用
  Then 窗口透明度自动恢复为 60%

Scenario: 透明度最小值边界
  Given 用户尝试将透明度滑块拖至最左侧
  Then 滑块停止在 20% 位置
  And 窗口保持可见（20% 不透明度）
```

### 6.2 鼠标悬停自动恢复不透明

```gherkin
Scenario: 鼠标进入窗口触发恢复
  Given 窗口透明度设置为 50%
  And 悬停恢复功能已开启
  When 鼠标从窗口外移入窗口内
  Then 窗口透明度在 150ms 内渐变至 100%

Scenario: 鼠标离开窗口延迟恢复
  Given 窗口因悬停恢复处于 100% 不透明状态
  When 鼠标移出窗口
  Then 等待 300ms 后窗口透明度在 200ms 内渐变回设定值

Scenario: 快速移入移出不闪烁
  Given 窗口透明度设置为 40%
  When 鼠标快速划过窗口边缘（停留时间 < 300ms）
  Then 窗口透明度不发生明显闪烁变化

Scenario: 关闭悬停恢复功能
  Given 用户在设置中关闭悬停恢复功能
  When 鼠标移入窗口
  Then 窗口透明度保持不变
```

### 6.3 穿透模式

```gherkin
Scenario: 开启穿透模式后非交互区域可穿透
  Given 穿透模式已开启
  And AI_Cue 窗口下方有其他应用窗口
  When 用户点击 AI_Cue 窗口的空白背景区域
  Then 点击事件被下方应用接收

Scenario: 穿透模式下交互区域仍可操作
  Given 穿透模式已开启
  When 用户点击 AI_Cue 的发送按钮
  Then 按钮正常响应点击事件

Scenario: 标题栏始终不穿透
  Given 穿透模式已开启
  When 用户点击穿透模式开关图标
  Then 穿透模式被关闭

Scenario: 快捷键切换穿透模式
  Given 穿透模式已关闭
  When 用户按下 Ctrl+Shift+T
  Then 穿透模式被开启
  And 标题栏穿透开关图标状态更新

Scenario: 穿透模式不持久化
  Given 穿透模式已开启
  When 用户关闭并重新启动应用
  Then 穿透模式为关闭状态
```

### 6.4 窗口位置和大小记忆

```gherkin
Scenario: 窗口位置被记忆
  Given 用户将窗口拖拽至屏幕右下角 (x=1000, y=500)
  When 用户关闭并重新启动应用
  Then 窗口出现在 (x=1000, y=500) 位置

Scenario: 窗口大小被记忆
  Given 用户将窗口缩放至 500x700 像素
  When 用户关闭并重新启动应用
  Then 窗口大小恢复为 500x700 像素

Scenario: 多显示器场景 - 副显示器断开
  Given 用户将窗口移动至副显示器
  And 用户关闭应用
  When 用户断开副显示器后启动应用
  Then 窗口出现在主显示器中央位置

Scenario: 首次启动使用默认位置
  Given 应用首次安装，无历史配置
  When 用户启动应用
  Then 窗口出现在主显示器右下角区域
  And 窗口大小为默认的 400x600 像素
```

### 6.5 紧凑模式

```gherkin
Scenario: 切换至紧凑模式
  Given 当前为完整模式
  When 用户点击标题栏的紧凑模式按钮
  Then 窗口在 200ms 内收缩为紧凑尺寸
  And 仅显示最新一条 AI 回答

Scenario: 紧凑模式显示最新 AI 回答
  Given 当前会话有 3 轮对话
  And 最新 AI 回答内容为"这是最新的回答内容"
  When 用户切换至紧凑模式
  Then 窗口显示"这是最新的回答内容"
  And 不显示历史消息和用户消息

Scenario: 紧凑模式内容截断
  Given 最新 AI 回答长度超过 200 字符
  When 用户切换至紧凑模式
  Then 内容截断至 200 字符并显示"..."
  And 显示"展开查看完整回答"链接

Scenario: 紧凑模式下实时更新
  Given 当前为紧凑模式
  When AI 产生新的流式回答
  Then 紧凑窗口内容实时更新显示新回答

Scenario: 从紧凑模式恢复
  Given 当前为紧凑模式
  When 用户双击内容区域
  Then 窗口在 200ms 内扩展为完整模式
  And 显示完整对话界面

Scenario: 紧凑模式位置独立记忆
  Given 完整模式窗口位于 (100, 100)
  And 紧凑模式窗口位于 (800, 50)
  When 用户在完整模式和紧凑模式间切换
  Then 各模式恢复到各自记忆的位置

Scenario: 紧凑模式状态持久化
  Given 用户在紧凑模式下关闭应用
  When 用户重新启动应用
  Then 应用以紧凑模式启动
```
